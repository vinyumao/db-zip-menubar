## 1. 目标

做一款 macOS **菜单栏 App**，在文件进入监听目录且名称匹配业务 zip 规则时，用现代 wizard 引导用户完成与现有 `.command` **行为对等** 的流程：确认 → 移动/解压 → 复制到本地路径或 ADB 设备（常用文件或整目录）→ 维护路径/设备历史。

不依赖油猴/浏览器扩展；下载来源可以是任意渠道，只要文件落到监听目录。

## 2. 非目标（第一期不做）

- App Store / 公证 / 自动更新
- 沙盒化
- 捆绑 platform-tools
- 匹配规则可视化配置
- 设备远程目录可配置
- 启动时扫描 Downloads 遗留 zip
- 调用旧 bash 作为执行引擎（全量 Swift 重写）

## 3. 用户与分发

- 仅本人本机使用
- 非沙盒（需访问任意本地路径、调用 `adb`）
- 本地 Xcode 构建/运行即可；不做 Developer ID 公证流程

## 4. 核心用户流程

### 4.1 自动命中（主路径）

1. App 常驻（默认登录打开），监听配置的目录（默认 `~/Downloads`）。
2. 出现疑似目标文件 → **临时名过滤 + size 稳定** → 应用写死匹配规则。
3. 命中后：**系统通知 + 菜单栏角标**；不强制抢前台焦点。
4. 用户点通知或菜单 → 打开 **独立 wizard 小窗**。
5. 确认步三选一：
   - **处理**：进入解压与后续复制流程
   - **忽略**：按「该文件身份」记住，直至文件删除或内容身份变化，不再提示
   - **稍后**：关闭窗口，任务留在「待处理」，**不自动再弹**
6. 处理成功后：移动到 `dbRoot/YYYYMMDD/`、解压、删除 zip、Finder 打开解压目录，再选复制目标。

### 4.2 手动选择 zip

- 菜单提供「选择 zip…」
- 默认仍跑匹配规则；不匹配时展示原因，允许 **「仍要处理」** 强制继续
- 之后与「处理」同一套 wizard

### 4.3 复制目标（与现脚本对等）

解压完成后循环选择：

1. **指定路径** → 历史路径列表（标「上次」）/ 其他（手输）/ 返回  
   - 再选内容模式：常用文件 / 整目录 / 返回  
   - 新手输路径：询问是否记住（已在历史中则只 touch，不询问）
2. **指定设备** → 列出 `adb devices` 中 `device` 状态设备（标「上次」）/ 刷新 / 返回  
   - 再选内容模式  
   - 推送到写死的首选目录，失败则回退 `/sdcard/db`
3. **取消**：结束复制，保留已解压目录

### 4.4 失败收场

任一复制步骤失败时：

- 保留已解压产物
- 错误页提供：**重试** / **换目标** / **在 Finder 打开解压目录** / 取消

## 5. 匹配与完成判定

### 5.1 目标 zip 规则（写死，对齐现脚本 `is_target_zip`）

文件名同时满足：

1. 以 `.zip` 结尾（大小写按实现时统一：建议大小写不敏感，默认业务名为小写 `.zip`）
2. 下划线 `_` 出现次数 ≥ 2
3. 匹配 `(^|_)[0-9]{9}_`（含 9 位数字段）
4. 匹配 `_[0-9]{10,}\.zip$`（时间戳段）

### 5.2 下载完成判定（组合）

- 忽略浏览器临时名/后缀，例如：`.crdownload`、`.download`、以 `.` 开头的未完成名、以及仍带下载临时后缀的条目（实现时按常见浏览器列表维护）
- 正式 `.zip` 出现后：连续 **2–3 秒** 文件 `size` 不变（建议默认 2.5s，常量可调）才进入匹配与入队

### 5.3 冷启动

- **不**扫描启动前已存在的匹配文件
- 仅处理监听开始之后的新建/稳定完成事件
- 遗留文件靠「选择 zip…」手动处理

### 5.4 队列

- 多文件命中：**串行队列**，同一时间只跑一个 wizard 流程
- 「稍后」的项留在待处理列表，不自动弹出；用户从菜单打开
- 「忽略」的项不入待处理

### 5.5 忽略身份

记住至少：`标准化路径` + `fileSize` + `mtime`（或等价内容指纹）。  
任一变化视为新文件，可再次提示。

## 6. 解压与目录布局

### 6.1 默认路径（可在设置修改）

| 配置项 | 默认值 |
|--------|--------|
| 监听目录 | `~/Downloads` |
| db 根目录 | `~/Downloads/db` |

产出路径：`{dbRoot}/{yyyyMMdd}/{zipBaseName}/`  
zip 先移入 `{dbRoot}/{yyyyMMdd}/{zipName}`；若同名已存在，则改名为 `{base}_{HHmmss}.zip`（对齐现脚本）。

### 6.2 解压后

- 解压到与 zip 主名对应的目录
- **删除** zip（对齐现脚本）
- 用 Finder 打开解压目录

解压实现：优先调用系统 `ditto -x -k`，不可用时再退到其它 Foundation/第三方 ZIP 方案；错误需可读。

## 7. 内容模式

### 7.1 常用文件（对齐 `collect_common_files`）

在解压目录 **一层** 内收集：

- 最新修改的 `*.db`（排除 `*.db-*`）
- 最新修改的 `*.si`
- 所有匹配 `*_dYYYYMMDD(.N)?.log` 中 **日期最大** 的那一天的全部分片

若常用文件集合为空，则报错，不可继续该模式。

### 7.2 整目录

复制解压目录下 **一层子文件/子文件夹**（不包含解压根自身），对齐 `copy_tree_children_*`。

## 8. 本地复制

- 将选中内容 `copy` 到用户目标目录（目录不存在则创建）
- 路径历史：最多保留 10 条；按最近使用排序；列表首项标「上次」
- 新手输且确认记住 → 写入历史；历史已有 → 只更新时间戳

## 9. 设备复制（ADB）

### 9.1 adb 定位

按顺序解析，设置可覆盖：

1. 用户在设置中指定的绝对路径
2. `PATH` 中的 `adb`
3. 常见位置：`~/Library/Android/sdk/platform-tools/adb`

找不到则在设备流程中提示安装/配置，并提供跳转设置。

### 9.2 设备列表

- 解析 `adb devices -l`
- 仅 `state == device` 进入可选列表
- 展示 `brand model (sn)`；brand/model 优先来自 `-l` 的 model/product，不足再用 `getprop`
- 不可用设备数量可提示，但不列入选项
- 支持刷新；历史中最近设备标「上次」

### 9.3 远程目录（写死）

1. 首选：`/sdcard/Android/data/com.baigong.recopos/files/baigong/recopos`
2. 回退：`/sdcard/db`

`mkdir -p` 需用哨兵输出确认成功（对齐现脚本，避免旧 adb 吞退出码）。首选失败则回退；回退成功时 UI 警告「请手动再拷到项目目录」。两者皆失败则错误页可重试。

`adb push` 逐文件进行；失败则进入错误收场，不假装成功。

## 10. 数据与迁移

### 10.1 App 存储

- 根目录：`~/Library/Application Support/db-zip-menubar/`（或 bundle id 对应 Application Support）
- 至少包含：
  - `history.json`：`paths[]` / `devices[]`（字段对齐旧格式：`path/ts`，`sn/brand/model/ts`，`MAX=10`）
  - `settings.json`：监听目录、db 根、adb 路径、登录项偏好、稳定等待秒数等
  - `ignored.json`：已忽略文件身份
  - `pending` 状态：稍后未完成的任务（路径/身份），App 重启后仍可从菜单打开

### 10.2 迁移

- 首次启动若存在 `~/.config/db-zip-copy/history.json`：
  - 导入 `paths` / `devices` 到 App `history.json`
  - 写迁移标记，避免重复导入覆盖用户新数据（已迁移则跳过，除非设置提供「重新导入」——第一期可不做重新导入）
- 不删除旧文件（旧脚本归档后仍可能只读对照）

## 11. UI 信息架构

### 11.1 菜单栏

- 图标 + 角标（待处理数量）
- 菜单项建议：
  - 待处理（子列表或打开队列面板）
  - 选择 zip…
  - 开始/暂停监听（可选；默认监听中）
  - 设置…
  - 退出

### 11.2 Wizard（独立窗口）

建议步骤（可返回上一步，除非已不可逆）：

1. 确认文件（名、路径、匹配结果/强制原因）
2. 执行移动+解压（进度/日志）
3. 选择复制位置：路径 / 设备 / 取消
4. 内容模式
5. 路径选择或设备选择
6. 执行复制（进度）
7. 成功摘要或错误收场

不可逆点：用户确认「处理」且移动/解压开始后，取消不应默默丢产物；失败走第 4.4 节。

### 11.3 设置

- 监听目录、db 根目录
- adb 路径（浏览文件）
- 登录时打开（默认开）
- 完成判定等待时长（可选暴露）
- 打开 Application Support / 显示版本

### 11.4 通知

- 命中待确认时发系统通知；点击打开对应 wizard/待处理项
- 不在用户未点开时强行 `activate` 抢焦点

## 12. 架构模块（Swift）

建议边界清晰的模块，便于单测与替换：

| 模块 | 职责 |
|------|------|
| `DownloadWatcher` | FSEvents/目录监听，临时名过滤，size 稳定，产出候选 URL |
| `ZipMatcher` | `is_target_zip` 纯函数 |
| `JobQueue` | 串行队列；与 pending/ignored 协作 |
| `UnpackService` | 建日期目录、移 zip、解压、删 zip、打开 Finder |
| `CommonFilesCollector` | 常用文件收集 |
| `LocalCopyService` | 本地复制 |
| `AdbClient` | 找 adb、devices、mkdir 哨兵、push |
| `DeviceCopyService` | 首选/回退目录 + push |
| `HistoryStore` | 读写历史、迁移 |
| `SettingsStore` | 设置 |
| `IgnoreStore` / `PendingStore` | 忽略与稍后 |
| `WizardCoordinator` | 步骤状态机 |
| `MenuBarApp` | 菜单、角标、通知入口 |

进程模型：单进程菜单栏 App；所有 `adb`/解压通过 `Process` 调用，注意主线程不阻塞（后台任务 + UI 进度）。
